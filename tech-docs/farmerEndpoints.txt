| Method   | Route                             | Access | Description                     |
| -------- | --------------------------------- | ------ | ------------------------------- |
| `POST`   | `/api/farmer-request`             | User   | Submit request                  |
| `GET`    | `/api/farmer-request/my`          | User   | View my request                 |
| `PUT`    | `/api/farmer-request/:id`         | User   | Update pending request          |
| `DELETE` | `/api/farmer-request/:id`         | User   | Delete pending request          |
| `GET`    | `/api/farmer-request`             | Admin  | List all requests               |
| `GET`    | `/api/farmer-request/:id`         | Admin  | Get single request              |
| `PATCH`  | `/api/farmer-request/:id/approve` | Admin  | Approve + create Farmer profile |
| `PATCH`  | `/api/farmer-request/:id/reject`  | Admin  | Reject request                  |

      FarmerRequest
What happens?

The user sends their farmer application.

The service should:

Identify the logged-in user from req.user._id.
Check that the user exists.
Check whether they already have an active/pending request.
Create the request.
Set status = "pending".

The user does not send their userId.

This prevents a user from asking:

/my?userId=someone-else

and seeing another user's request.

The service checks:

request.userId === req.user._id

AND:

request.status === "pending"

So:

Owner + Pending
       │
       ├── YES → Update
       │
       └── NO  → Reject

If the request is already approved or rejected, the user should not be able to modify it.

          /      \
         ▼        ▼
 FarmerRequest   Farmer
    approved     created

The important business logic is:

Find Request
     │
     ▼
Is status "pending"?
     │
   YES
     │
     ▼
Create Farmer Profile
     │
     ▼
Update Request
status = "approved"

So approval effectively changes the user's account from:

User
 │
 │ farmer request
 ▼
FarmerRequest
 │
 │ admin approves
 ▼
Farmer Profile

Ideally, this should be handled as an atomic/transactional operation, so you don't end up with an approved request but no Farmer profile if something fails midway.

The core rules
Endpoint	Who	Important check
POST /farmer-request	User	Don't already have a pending request
GET /farmer-request/my	User	Use req.user._id
PUT /farmer-request/:id	User	Ownership + pending status
DELETE /farmer-request/:id	User	Ownership + pending status
GET /farmer-request	Admin	Admin role
GET /farmer-request/:id	Admin	Admin role
PATCH /farmer-request/:id/approve	Admin	Pending → create Farmer → approved
PATCH /farmer-request/:id/reject	Admin	Pending → rejected
